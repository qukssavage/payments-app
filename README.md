# Учёт оплат учебного центра

Мини-сервис для учёта учеников, их оплат и должников за месяц.
Тестовое задание Ecomdev: API (часть 1) + веб-страница (часть 2, вариант Б).

**Стек:** Python 3.10+, FastAPI, SQLite (встроенный `sqlite3`, SQL без ORM), pytest.

## Запуск с нуля

Нужны Python 3.10 или новее и Git.

```bash
git clone https://github.com/qukssavage/payments-app.git
cd payments-app

python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
uvicorn main:app --reload
```

После запуска:

- **веб-страница:** http://127.0.0.1:8000/ — должники и форма оплаты (удобна на телефоне);
- **документация API (Swagger):** http://127.0.0.1:8000/docs — здесь можно создать учеников и проверить все запросы.

База данных `payments.db` создаётся автоматически при первом запуске. Учеников удобнее всего добавить через `/docs` → `POST /students`.

### Тесты

```bash
pytest -v
```

Тесты работают на отдельной временной базе и не трогают `payments.db`.

## API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/students` | Создать ученика |
| GET | `/students` | Список учеников |
| GET | `/students/{id}` | Один ученик |
| PATCH | `/students/{id}` | Изменить ученика (только переданные поля) |
| DELETE | `/students/{id}` | Удалить ученика вместе с его оплатами |
| POST | `/payments` | Добавить оплату (дата по умолчанию — сегодня) |
| GET | `/students/{id}/payments` | Оплаты ученика |
| GET | `/debtors?month=YYYY-MM` | Должники за месяц (без параметра — текущий месяц) |

Пример ученика:

```json
{"name": "Алишер Каримов", "phone": "+998901234567", "group_name": "Python-1", "monthly_fee": 500000}
```

Пример ответа `/debtors`:

```json
[{"id": 2, "name": "Дилноза Юсупова", "phone": "+998911112233", "group_name": "Python-1",
  "monthly_fee": 500000, "paid": 0, "debt": 500000}]
```

## Принятые решения

- **Должник** — ученик, у которого сумма оплат с датой внутри месяца меньше его месячной суммы. Ученики без единой оплаты попадают в список с полным долгом.
- **Учитываются только ученики, добавленные в систему до конца месяца** — чтобы за прошлые месяцы не появлялись те, кто ещё не учился.
- **Переплата не переносится** на следующий месяц: каждый месяц считается отдельно.
- **Месячная сумма — текущая:** при её изменении долги за прошлые месяцы пересчитываются по новой сумме.
- **Деньги хранятся целыми числами** (сумы), без float — чтобы не было ошибок округления.
- **Удаление ученика удаляет и его оплаты** (`ON DELETE CASCADE`).
- **Валидация:** сумма оплаты > 0, месячная сумма ≥ 0, телефон — 9–15 цифр с необязательным `+`, дата оплаты не в будущем, месяц строго `YYYY-MM`. Ошибки возвращаются с кодом 422 (неверные данные) или 404 (ученик не найден).
- **Даты считаются по местному времени сервера.**

## Что бы я улучшил, будь у меня ещё неделя

1. **Дата зачисления ученика** отдельным полем (сейчас её роль играет дата добавления в систему) и запрет оплат с датой раньше зачисления. Сейчас можно внести оплату, например, за 2022 год ученику, добавленному в 2026-м.
2. **История месячной суммы:** хранить, с какого месяца действует сумма, чтобы её изменение не пересчитывало старые долги.
3. **Архив вместо удаления:** не стирать ученика и его оплаты, а помечать как выбывшего — история оплат важна для учёта.
4. **Авторизация** для страницы и API, а также журнал: кто и когда внёс оплату.
5. **Docker Compose и PostgreSQL** для запуска на сервере, плюс Telegram-бот (вариант А) поверх готового API.
